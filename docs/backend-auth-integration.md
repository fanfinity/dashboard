# Dashboard ↔ Backend auth integration — plan

**Status:** ✅ implemented 2026-07-21 (scope as agreed: auth + API client only, no new
screens). Deviations from the plan below:

- The client is **generated by orval** from the backend's OpenAPI spec instead of the
  hand-rolled `useApi.js` sketched below: `orval.config.js` + `openapi/sfere-api.json`
  (snapshot; `pnpm openapi` re-pulls from staging and regenerates `src/api/`). Output is
  typed fetchers (`getMe()`, …) plus `@tanstack/vue-query` composables (`useGetMe()`, …;
  plugin registered in `src/boot/vue-query.js`). The auth behavior specified below
  (Bearer token, single force-refresh retry on 401, error with status + detail) lives in
  `src/api/mutator.js` (`customFetch` / `ApiError`).
- Real paths are versioned: **`/v1/me`**, `/v1/accounts`, … (the plan said `/me`).
  Errors are RFC 9457 `application/problem+json`.
- Verified end-to-end against staging 2026-07-21 (throwaway tenant user → `/v1/me` →

  1. The backend rejects unverified emails (`401 Email is not verified`) — the
     dashboard's email/password sign-up never sends a verification email, so
     self-signed-up users can't call the API until that flow exists (or the backend

  2. ~~Staging `CORS_ALLOW_ORIGINS` allows only `https://dashboard-staging.fanfinity.io`~~

## Context

The Fanfinity backend (`../backend`) now verifies **Google Cloud Identity Platform**
ID tokens and enforces account-scoped RBAC (see its README § "Auth & multi-tenancy").
The dashboard already signs users into Identity Platform (project `koratona-9791a`,
tenant `fanfinity-app-fcsgt`) via the Firebase Auth SDK — but today it **never sends
that token to any backend**: auth only gates client-side routing, and the Live-Events
data comes from a _different_ system (`console.fanfinity.io`) through a dev proxy.

Goal of this change: give the dashboard a small authenticated API client for the new
backend and populate the signed-in user's accounts/role on login, so future screens can
be built on top. We are **not** wiring existing composables (`useLiveEvents`, `useJitsu`,
`useConnectorCatalog`) to the new backend — those keep hitting `console.fanfinity.io`.

> `/japi` dev proxy were deleted outright, and `console.fanfinity.io` is no longer in the

## Backend prerequisite — CORS ✅ DONE

The dashboard runs on a different origin than the API (e.g. `localhost:9000` → the
backend on `localhost:8080` in dev; `app.sfere.io` → `api.sfere.io` in prod),
so browser `fetch` with an `Authorization` header needs CORS.

**Implemented in the backend** (branch `feat/cors-middleware`): FastAPI `CORSMiddleware`
in `create_app()`, driven by the `CORS_ALLOW_ORIGINS` setting (comma-separated;
defaults to `http://localhost:9000`, empty disables). It allows the `Authorization` and
`X-Support-Token` headers and methods `GET, POST, DELETE, OPTIONS`. **For each deployed
environment, set `CORS_ALLOW_ORIGINS` to the dashboard's real origin** (e.g.
`https://app.sfere.io`) — the dashboard side needs no CORS work. Firebase Hosting PR
preview channels get a fresh origin per PR and so cannot be listed; staging admits
them through `CORS_ALLOW_ORIGIN_REGEX` instead, production deliberately does not.

## Dashboard changes

### 1. New env var — `VITE_API_BASE`

Add to `.env` (and document alongside the existing keys):

```

# (make run in ../backend); staging/prod use the deployed host.
VITE_API_BASE=http://localhost:8080
```

Deployed builds set `VITE_API_BASE=https://api-staging.sfere.io` (staging and PR
previews) or `https://api.sfere.io` (prod). The `api*.fanfinity.io` hosts remain
attached to the same ingress as aliases.

### 2. New API client — `src/composables/useApi.js`

A thin `fetch` wrapper that attaches the Identity Platform ID token. Mirror the existing
module-singleton composable style (`useAuth.js`, `useJitsu.js`).

- Import `auth` from `@/firebase`.
- Get a fresh token with `await auth.currentUser.getIdToken()` (the SDK auto-refreshes;
  it returns a valid token, refreshing if near expiry). If `auth.currentUser` is null,
  throw / return early — the caller isn't signed in.
- Build the URL as `${(import.meta.env.VITE_API_BASE || 'http://localhost:8080').replace(/\/$/, '')}${path}`.
- Set headers: `Authorization: Bearer <token>`, `Content-Type: application/json` (for
  bodies), `Accept: application/json`.
- Parse JSON; throw an `Error` carrying `status` + the backend's `{ detail }` on non-2xx.
- **401 handling:** on a 401, retry **once** after `auth.currentUser.getIdToken(true)`
  (force refresh); if it still 401s, surface the error (and optionally `signOut`).
- Expose helpers: `apiGet(path)`, `apiPost(path, body)`, `apiDelete(path)`.

Sketch:

```js
// src/composables/useApi.js
import { auth } from '@/firebase'

const BASE = (import.meta.env.VITE_API_BASE || 'http://localhost:8080').replace(
  /\/$/,
  ''
)

async function request(path, { method = 'GET', body, _retried = false } = {}) {
  if (!auth.currentUser) throw new Error('Not signed in')
  const token = await auth.currentUser.getIdToken()
  const res = await fetch(`${BASE}${path}`, {
    method,
    headers: {
      Authorization: `Bearer ${token}`,
      Accept: 'application/json',
      ...(body ? { 'Content-Type': 'application/json' } : {})
    },
    ...(body ? { body: JSON.stringify(body) } : {})
  })
  if (res.status === 401 && !_retried) {
    await auth.currentUser.getIdToken(true) // force refresh, retry once
    return request(path, { method, body, _retried: true })
  }
  if (!res.ok) {
    const detail = await res.json().catch(() => ({}))
    const err = new Error(detail.detail || `Request failed (${res.status})`)
    err.status = res.status
    throw err
  }
  return res.status === 204 ? null : res.json()
}

export const apiGet = path => request(path)
export const apiPost = (path, body) => request(path, { method: 'POST', body })
export const apiDelete = path => request(path, { method: 'DELETE' })
```

### 3. Session bootstrap — `src/composables/useMe.js` (or fold into `useAuth`)

Module-scoped reactive `me` + `memberships`, loaded from `GET /me` once the user is
signed in. This is what future account-scoped screens will read.

- `export const me = ref(null)` and `export const memberships = ref([])`.
- `async function loadMe()` → `const data = await apiGet('/me'); me.value = data.user;
memberships.value = data.memberships` (each item is `{ account, role }`).
- Trigger it when auth becomes ready with a signed-in user. Cleanest: in
  `useAuth.js`'s `onAuthStateChanged` callback, after setting `user.value`, if a user is
  present call `loadMe()` (and clear `me`/`memberships` on sign-out). Keep it best-effort
  (swallow errors into a ref) so a backend hiccup doesn't block routing.

1. Backend: `cd ../backend && make run` (needs local Postgres; `make migrate` first).
   Ensure CORS allows `http://localhost:9000`.
2. Dashboard: set `VITE_API_BASE=http://localhost:8080`, `quasar dev`.
3. Sign in. In the browser Network tab, confirm a `GET /me` request goes out with an

   appears in a subsequent `/me`.
